# ADR 002: Selection of Singly Linked List over Doubly Linked List

## Status
Accepted

## Context
When implementing the Linked List structure, we had to choose between a Singly Linked List (where nodes only point to the next element) and a Doubly Linked List (where nodes point to both the next and previous elements).

## Decision
We have decided to implement a **Singly Linked List**.

## Justification
- **Memory Efficiency**: A Singly Linked List requires only one pointer per node (`next`), reducing the memory overhead per element compared to a Doubly Linked List.
- **Complexity Focus**: The primary goal of this project is to demonstrate fundamental pointer manipulation and memory management. A Singly Linked List provides the necessary complexity to prove these skills without unnecessary overhead for the current requirements.
- **Performance**: For the intended use cases (insertion at head and sequential traversal), the performance is identical to a Doubly Linked List.

## Consequences
- **Traversal Constraint**: The list can only be traversed in one direction (from head to tail).
- **Deletion Complexity**: To remove a node, we must maintain a pointer to the previous node during traversal, as we cannot move backwards.
