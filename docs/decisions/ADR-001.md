# ADR 001: Use of `void**` for Generic Storage

## Status
Accepted

## Context
The goal is to implement a Dynamic Array that can store any data type (integers, strings, custom structs). In C, there are two primary ways to achieve genericity:
1. Store data as a contiguous block of bytes (`void*` and manual offset calculation).
2. Store pointers to the data (`void**`).

## Decision
We have decided to use `void**` (an array of pointers). Each element in the Dynamic Array will be a pointer to the actual data stored elsewhere in memory.

## Justification
- **Simplicity**: It eliminates the need to store and track the size of the data type (element size) within the `struct`.
- **Efficiency**: Accessing an element is a constant time $O(1)$ operation, as we only need to access the pointer at the given index.
- **Flexibility**: It allows the array to hold pointers to objects of different sizes or types simultaneously if needed.

## Consequences
- **Extra Indirection**: Accessing the data requires two memory accesses (one for the pointer and one for the actual data).
- **Memory Responsibility**: The user of the library is responsible for allocating and freeing the memory of the elements themselves; the library only manages the memory of the pointer array.
